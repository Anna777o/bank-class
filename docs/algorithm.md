# Описание алгоритма

## 1. Базовые классы (AbstractAccount / BankAccount)

1. **Инициализация счета:**
   - Проверка корректности валюты (RUB, USD, EUR, KZT, CNY).
   - Генерация короткого UUID (первые 8 символов), если ID не передан.
   - Установка базового статуса "active".

2. **Операция пополнения (deposit):**
   - Проверка статуса счета (если frozen/closed -> выброс исключения).
   - Валидация суммы (должна быть числом > 0).
   - Увеличение баланса.

3. **Операция снятия (withdraw) — базовая:**
   - Проверка статуса счета.
   - Валидация суммы (> 0).
   - Проверка достаточности средств (amount <= balance).
   - Уменьшение баланса.

4. **Проверка статуса (_check_status):**
   - Если статус "frozen" → AccountFrozenError.
   - Если статус "closed" → AccountClosedError.
   - Вызывается ПЕРВОЙ строкой в любом методе, меняющем баланс.

---

## 2. SavingsAccount (Накопительный счёт)

**Наследуется от:** BankAccount.

**Дополнительные атрибуты:**
- `min_balance` — минимально допустимый остаток (по умолчанию 0).
- `interest_rate` — месячная ставка (например, 0.05 = 5%).

**Алгоритм withdraw (переопределён):**
1. Проверить статус счёта.
2. Валидировать сумму.
3. Проверить, что после снятия `balance - amount >= min_balance`.
   - Если нет → InvalidOperationError ("Баланс упадёт ниже минимального остатка").
4. Уменьшить баланс.

**Алгоритм apply_monthly_interest:**
1. Проверить статус счёта.
2. Рассчитать проценты: `interest = balance * interest_rate`.
3. Увеличить баланс на величину процентов.
4. Залогировать операцию.

## 3. PremiumAccount (Премиальный счёт)

**Наследуется от:** BankAccount.

**Дополнительные атрибуты:**
- `overdraft_limit` — максимальный размер овердрафта (по умолчанию 1000).
- `commission` — фиксированная комиссия за снятие (по умолчанию 50).

**Алгоритм withdraw (переопределён):**
1. Проверить статус счёта.
2. Валидировать сумму.
3. Рассчитать итоговую сумму к списанию: `total = amount + commission`.
4. Проверить, что `balance - total >= -overdraft_limit`.
   - Если нет → InsufficientFundsError ("Превышен лимит овердрафта").
5. Уменьшить баланс на `total` (баланс может уйти в минус в пределах overdraft_limit).
6. Залогировать удержание комиссии.

**Особенность:** баланс может быть отрицательным, но не меньше `-overdraft_limit`.

---

## 4. InvestmentAccount (Инвестиционный счёт)

**Наследуется от:** BankAccount.

**Дополнительные атрибуты:**
- `portfolio` — словарь вида `{"stocks": 0.0, "bonds": 0.0, "etf": 0.0}`.
- Допустимые типы активов: stocks, bonds, etf.

**Алгоритм invest(asset_type, amount):**
1. Проверить статус счёта.
2. Проверить, что `asset_type` входит в VALID_ASSETS → иначе InvalidOperationError.
3. Валидировать сумму (> 0).
4. Проверить, что `amount <= balance` → иначе InsufficientFundsError.
5. Уменьшить свободный баланс на `amount`.
6. Увеличить `portfolio[asset_type]` на `amount`.

**Алгоритм project_yearly_growth(growth_rates):**
1. Инициализировать `projected_total = 0`.
2. Для каждого актива в портфеле:
   - Взять ставку из growth_rates (по умолчанию 0, если не указана).
   - `projected_total += portfolio[asset] * (1 + rate)`.
3. Вернуть итоговую прогнозируемую стоимость.

**Пример ставок для демонстрации:**
- stocks → 10% (0.10)
- bonds → 4% (0.04)
- etf → 7% (0.07)

## 5. Полиморфизм

Все три класса переопределяют:
- `withdraw()` — своя логика списания (минимальный остаток / овердрафт+комиссия / базовый).
- `get_account_info()` — добавляет специфичные поля в словарь.
- `__str__()` — расширяет базовое представление (через `super().__str__()`).

## 6. Исключения (utils.py)

| Исключение | Когда выбрасывается |
|---|---|
| AccountFrozenError | Операция над замороженным счётом |
| AccountClosedError | Операция над закрытым счётом |
| InvalidOperationError | Невалидная сумма, валюта, тип актива, нарушение min_balance |
| InsufficientFundsError | Нехватка средств (с учётом овердрафта) |

---

## 7. Порядок проверок 

В каждом методе, меняющем баланс, соблюдается строгий порядок:
1. **Статус счёта** (frozen/closed) — самое первое.
2. **Валидность суммы** (число, > 0).
3. **Бизнес-правило** (min_balance / overdraft / достаточно ли средств).
4. **Изменение баланса**.

Нарушение порядка (например, изменение баланса до проверки статуса) считается багом.
